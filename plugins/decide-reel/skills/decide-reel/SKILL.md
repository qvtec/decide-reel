# decide-reel

決めることを1件ずつ見せて、その場で選んでもらうためのページを作る。
ページはHTML1ファイルで、外部への通信をしない（フォント・音・ライブラリをすべて内蔵）。

## 流れ

1. **材料を読む**：ユーザーが渡した資料・議事録・チャット・ファイルを読む。足りなければ、何を決めたいかを1回だけ聞く。
2. **決めることを洗い出す**：下の「論点の作り方」に沿ってJSONを書く。
3. **ビルドする**：このSKILL.mdと同じフォルダにある `scripts/build.py` を使う。

   ```bash
   python3 <このスキルのフォルダ>/scripts/build.py <data.json> <out.html>
   ```

   置き場所はユーザーの指定に従う。指定がなければ、作業フォルダに `decide-reel/<YYYY-MM-DD>-<短い英数字の名前>.json` と `.html` を並べて置く。JSONを残しておけば、あとで直してビルドし直せる。
4. **伝える**：HTMLのパスと、論点の一覧（タイトルだけ）を短く返す。各論点の中身はチャットに書き写さない。ページで見てもらう。

ビルドでエラーが出たら、表示された項目を直してもう一度ビルドする。

## 論点の作り方

- **1論点＝1つの問い**。「AとBどっちにする？」で答えられる粒度に分ける。1つの問いに2つの判断が混ざっていたら分ける。
- **並べる順番**：ほかの論点の前提になるものを先にする。
- **説明は図でする**。文で書く前に、絵で見せられないかを考える。1論点に図は1つ（`figure`）。できるだけ全部の論点に付ける。
  - 数を比べる（票数・件数・費用）→ `bars`
  - 全体の内訳（割合・担当の偏り）→ `donut`
  - 効く数字が1〜3個（予算・人数・期限）→ `stats`
  - 手順のどこを決めるか → `flow`（`at` で決める段を黄色にする）
  - それ以外（しくみ・範囲・前後の違い・関係・構成・選ぶと何が変わるか）→ `svg` で説明図を描く。下の「SVGの描き方」に従う。
  - 数字を作らない。資料にない数字は図にしない。
- **選択肢には `icon` を描く**。下の「SVGの描き方」のアイコンの形で、選択肢ごとに違いがひと目でわかる絵を描く。選択肢どうしで似た絵にしない。絵文字を入れてもよいが、OSで絵柄が変わるのでSVGを優先する。
- **材料（claims / facts / unknowns）は合わせて3件まで**、図があるときは2件まで。図で言えたことは材料に書かない。
  - `claims`：資料の言い分の芯を一言で。`source` には資料名を短く。言っていないことは足さない。食い違っていれば両方並べる。
  - `facts`：資料で確かめられる事実だけを一言で。推測は入れない。
  - `unknowns`：決めるのに効くのに、わかっていないこと。
- **options**：2〜3件（最大4件）。互いに重ならない選び方にする。`label` だけで伝わるようにし、`note` は補足が要るときだけ短く付ける。選択肢は label だけが順に読み上げられる（記号と note は読まない）ので、label は声に出して自然な言葉にする。どれかに肩入れしない（ユーザーにおすすめを聞かれたときだけ、note に書く）。「その他」と「あとで決める」はページ側が自動で出すので、options に入れない。
- **narrate（要点の一言）**：図と材料が出るときに読み上げる1〜2文。画面の文を読み上げるのではなく、図と材料から言える「つまり何か」を話し言葉で言う。数字は丸めて、比べる・対立する・足りないの要点だけにする。どれかの選択肢に肩入れしない。40字以内。
  例：○「希望は隔週が少し多め。ただ、回数より中身を厚くしたい声もあります」 ✕「アンケートでは隔週派が12人、月1派が9人でした。ふりかえりでは…」（画面の読み上げになっている）
- **文はとにかく短く**。見出しの言葉にする。理由・経緯・数字の細部は削る。読み上げは問い・narrate・選択肢と、まとめの締めの一言だけ。

  | 項目 | 目安 |
  |---|---|
  | `title` | 12字以内（目次とまとめに出る） |
  | `question` | 24字以内 |
  | `narrate` | 40字以内 |
  | `claims[].text` / `facts` / `unknowns` | 16字以内 |
  | `claims[].source` | 8字以内 |
  | `options[].label` | 10字以内 |
  | `options[].note` | 14字以内・なくてよい |
  | 図のラベル | 8字以内。`bars`・`donut`・`flow` は5件、`stats` は3件まで |

  資料の `title` と各論点の `title` は、改行したい位置に `\n` を入れられる（例 `"集客の打ち手、\nやる・やらない"`）。

  例：✕「発表の準備が重いので、回数より1回の中身を厚くしたいという声が多かった」→ ○「回数より中身を厚く」。✕ 事実「隔週派12人、月1派9人」→ ○ `bars` の図にする。ビルドすると、目安を超えた項目が警告で出るので、直してからビルドし直す。

## SVGの描き方

ページの見た目（白地・黒の太線・青のアクセント）に揃える。線はページ側で描かれていくように動く。

- **色**：線は `#111318`（アイコンは `currentColor`。選ぶと白に変わる）。強調は青 `#2b59ff`、薄い面は `#e8eeff`、注意は赤 `#ff5a5f`、黄 `#ffd84d`、薄い灰 `#9aa0ac`、緑 `#10b06f`、白 `#ffffff`。この色以外は使わない。ページ側でテーマの色に読み替えるので、テーマが何でもこの色で描く。
- **線**：`fill='none'`、`stroke-linecap='round'`、`stroke-linejoin='round'`。太さはアイコン3、説明図4。点線は `stroke-dasharray` で（描かれる動きはつかない）。
- **アイコン**：`viewBox='0 0 48 48'`、`stroke='currentColor'`、`stroke-width='3'`。要素は3〜6個ほどの線画にする。1か所だけ青を入れると締まる。
- **説明図**：`viewBox='0 0 560 220'`（材料が横に並ぶ幅。材料がないときも同じでよい）。左から右へ読む構図にする。文字は `<text>` で短いラベルだけ（`font-size='22' font-weight='800'`、`fill` を指定し `stroke='none'`）。文章を入れない。
- **使える要素**：`svg g path circle ellipse rect line polyline polygon text tspan defs linearGradient radialGradient stop title desc`。`<script>`・`<image>`・`<a>`・`<foreignObject>`・`<style>`、`on〜` 属性、`href`、外を指す `url()`、コメント（`<!-- -->`）や `<?…?>` はビルドで弾かれる。
- JSONの中に書くので、属性は `'` で囲むと書きやすい。説明図は8000字以内を目安に。

アイコンの例（持ち回り）：

```
<svg viewBox='0 0 48 48' fill='none' stroke='currentColor' stroke-width='3' stroke-linecap='round' stroke-linejoin='round'><path d='M39 19A16 16 0 0 0 10 14'/><path d='M9 5v10h10'/><path d='M9 29a16 16 0 0 0 29 5'/><path d='M39 43V33H29'/><circle cx='24' cy='24' r='3' fill='#2b59ff' stroke='none'/></svg>
```

説明図の例は `examples/sample.json` の3つめの論点（録画 → 社内に届く・社外には届かない）。

## 注意

- 材料に機密そうな情報があっても、ページは外に出ないので入れてよい。ただし共有のしかたはユーザーに任せる。

## JSONの形

```json
{
  "title": "資料全体のタイトル",
  "subtitle": "任意：何のための確認か1文で",
  "date": "任意：2026-11-05",
  "lang": "ja",
  "items": [
    {
      "title": "論点の短い見出し（目次に出る）",
      "question": "〜にする？ の形の問い",
      "narrate": "図と材料の要点を話し言葉で一言",
      "figure": { "type": "bars", "title": "任意：図の見出し", "unit": "人",
                  "data": [{ "label": "隔週", "value": 12 }, { "label": "月1", "value": 9 }] },
      "claims": [{ "source": "資料名", "text": "その資料の言い分" }],
      "facts": ["わかっていること"],
      "unknowns": ["まだわからないこと"],
      "options": [
        { "key": "A", "icon": "<svg viewBox='0 0 48 48' ...>...</svg>", "label": "選択肢", "note": "任意：短い補足" },
        { "key": "B", "icon": "<svg viewBox='0 0 48 48' ...>...</svg>", "label": "選択肢" }
      ]
    }
  ]
}
```

図（`figure`）の形：

| type | 中身 |
|---|---|
| `bars` | `data: [{label, value}]`（value は数）、任意で `unit`。いちばん大きい棒が濃い色になる |
| `donut` | `data: [{label, value}]`。`unit` があれば値、なければ割合（%）を出す |
| `flow` | `steps: ["段", ...]` か `[{icon, label}]`（icon はSVGか絵文字）。`at` に段の番号（0始まり）を入れると、その段を強調する |
| `stats` | `data: [{value, unit, label, icon}]`。整数の value は数え上げて出る |
| `svg` | `svg: "<svg viewBox='0 0 560 220' ...>...</svg>"`。その場で描く説明図 |

どれも任意で `title`（図の見出し）を付けられる。

任意の設定（トップレベル）：

| キー | 意味 |
|---|---|
| `theme` | 見た目。`navy`（既定・紺と金・やわらかい影）、`pop`（青黄緑の太枠）、`mono`（白黒＋朱）、`natural`（生成りとセージ・枠なし）、`slate`（グレーとティール・フラット）、`midnight`（濃紺の黒地に藍→シアンのグラデーション）、`carbon`（黒地にライム1色・角ばった）、`keynote`（白地に紫→青のグラデーション・枠なし）。ユーザーに指定がなければ聞かずに省く（`navy` になる） |
| `lang` | `ja`（既定）か `en`。画面の文言とナレーションの言語が変わる |
| `narration` | `false` で最初からナレーションOFF |
| `sound` | `false` で最初から効果音OFF |
| `closing` | まとめの画面で読む締めの一言（既定「おつかれさまでした。決めたことをまとめました。」）。変えるなら1文で |
| `rate` | 読み上げの速さ（既定 1.05） |
| `tts` | クラウドの声。`{"provider": "gcloud" \| "elevenlabs", "voice": "...", "model": "...", "rate": 1.05}`（model は ElevenLabs のみ、既定 `eleven_v4`）。下の「クラウドの声」 |
| `voice` | 最初に使う声の名前の一部（例 `Nanami`、`Google`）。指定がなければ Google の声 → Sayaka → Kyoko の順で、見つかったものを使う（Chrome は Google、Windows の Edge は Sayaka、Mac の Safari は Kyoko になる）。ページ下の声メニューで選び直すと、そちらを覚える |
| `footer` | 画面右下の小さな文字（「社外秘」など） |
| `id` | 回答の保存キー。同じタイトル・日付のページを別物として扱いたいときに使う |

各論点の `say` を入れると、問いの代わりにその文を読み上げる（略語の読みを直したいときなど）。`narrate` がない論点は、図と材料を声なしで見せる。`options[].say` を入れると、その選択肢の読み上げをその文に変えられる。

完成例は `examples/sample.json`。

## クラウドの声

ユーザーが Google Cloud TTS か ElevenLabs の声を使いたいと言ったとき、または JSON に `tts` があるとき、環境変数 `DECIDE_REEL_TTS` が設定されているときに使う。ビルドのときに音声を作ってHTMLに埋め込む。

```bash
python3 <このスキルのフォルダ>/scripts/build.py data.json out.html --tts gcloud       # 声は --voice ja-JP-Neural2-B など
python3 <このスキルのフォルダ>/scripts/build.py data.json out.html --tts elevenlabs   # 声は --voice <voice_id>
```

- キー：gcloud は `GOOGLE_TTS_API_KEY`（なければ `gcloud auth print-access-token` を使う）。ElevenLabs は `ELEVENLABS_API_KEY` と、声の `ELEVENLABS_VOICE_ID`。環境変数か `~/.config/decide-reel/env`（`NAME=値` の行）から読む。キーをJSON・コマンド・リポジトリの中に書かない。キーがないときは、ユーザーに `~/.config/decide-reel/env` に書いてもらう（チャットに貼ってもらわない）。
- 読み上げる文がビルドのときに外部へ送られる。ユーザーが頼んでいないのに、自分から使わない。
- 作った音声は data.json の隣の `.decide-reel-cache/` にとっておくので、文を直してビルドし直しても、変わった文の分しか作らない。
- 作れなかったときは警告を出し、ブラウザの読み上げのページを作る。警告が出たらユーザーに伝える。

## ページの使い方（ユーザーに聞かれたら伝える）

- 「はじめる」で再生。論点ごとに1ページで、上から 番号・問い → 図と材料 → 選択肢 の順に出て、選択肢が出たところで止まる。読み上げるのは問い、図が出たときの要点の一言、選択肢（読んでいるカードが光る。選ぶとそこで止まる）だけ。論点が変わるときは帯のワイプが入る。
- 選ぶ画面では、クリックするか数字キー（1〜3が選択肢、続く2つが「その他」「あとで決める」）で選ぶと、そのまま次の論点に進む。メモ欄は最初から出ているので、メモを残したいときは先に書いてから選ぶ。「その他」はメモが必須で、空なら進まずにメモ欄に移る（書いて Enter で次へ）。
- キー操作：Space 再生/一時停止、→ 選ぶ画面へ（選ぶ画面では次の論点へ）、← 前の論点、M 目次、V ナレーション、S 効果音、F 全画面、T テーマを順に切り替え（試すだけで保存はしない）。
- 下の丸い番号で論点を行き来できる。色は 緑＝決定、紫＝その他、黄＝あとで。
- 回答はそのブラウザに保存されるので、再読み込みしても消えない。まとめ画面の「回答をコピー」で、Slackや議事録に貼れる文になる。
- 声は下のバーのメニューで選べ、選んだ声はブラウザに覚えられる。クラウドの声を埋め込んだページでは、それが最初に選ばれている。ブラウザの読み上げは音量を上げられないので、声が小さいときはPCの音量で上げる。
- ナレーションはブラウザの読み上げ機能を使う。Chrome の既定の Google の声はオンラインの声で、読み上げる文が Google に送られる。気になる内容ならナレーションをOFFにする。
