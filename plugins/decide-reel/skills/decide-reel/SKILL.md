# decide-reel

決めることを1件ずつ見せて、その場で選んでもらうためのページを作る。
ページはHTML1ファイルで、外部への通信をしない（フォント・音・ライブラリをすべて内蔵）。

## 流れ

1. **材料を読む**：ユーザーが渡した資料・議事録・チャット・ファイルを読む。足りなければ、何を決めたいかを1回だけ聞く。
2. **決めることを洗い出す**：下の「論点の作り方」に沿ってJSONを書く。
3. **ビルドする**：このSKILL.mdと同じフォルダにある `scripts/build.py` を使う。

   ```bash
   python3 <このスキルのフォルダ>/scripts/build.py <data.json> <out.html>
   ```

   置き場所はユーザーの指定に従う。指定がなければ、作業フォルダに `decide-reel/<YYYY-MM-DD>-<短い英数字の名前>.json` と `.html` を並べて置く。JSONを残しておけば、あとで直してビルドし直せる。
4. **伝える**：HTMLのパスと、論点の一覧（タイトルだけ）を短く返す。各論点の中身はチャットに書き写さない。ページで見てもらう。

ビルドでエラーが出たら、表示された項目を直してもう一度ビルドする。

## 論点の作り方

- **1論点＝1つの問い**。「AとBどっちにする？」で答えられる粒度に分ける。1つの問いに2つの判断が混ざっていたら分ける。
- **並べる順番**：ほかの論点の前提になるものを先にする。
- **claims（資料の言い分）**：資料ごとに、言い分の芯を**一言**で書く（1件＝1カットで大きく出る）。`source` には資料名（「仕様書v2」「〇〇さんのSlack」など）を短く入れる。言っていないことは足さない。資料どうしで食い違っていれば、両方並べる。資料がない論点は省略してよい。
- **facts（わかっていること）**：資料から確かめられる事実だけを、**一言**で書く。推測は入れない。決めるのに効くものだけに絞る。
- **unknowns（まだわからないこと）**：決めるのに効くのに、わかっていないことを一言で。なければ省略する。
- **options**：2〜3件（最大4件）。互いに重ならない選び方にする。`note` にはその選択肢を選ぶと何が起きるかを1文で書く。どれかに肩入れしない（ユーザーにおすすめを聞かれたときだけ、note に理由つきで書く）。「その他」と「あとで決める」はページ側が自動で出すので、options に入れない。
- **文はとにかく短く**。1カットに1つずつ大きな文字で出すので、説明文ではなく見出しの言葉にする。理由・経緯・数字の細部は削る（必要なら `context` に1文だけ）。ナレーションは画面の文をそのまま読む。

  | 項目 | 目安 | 件数 |
  |---|---|---|
  | `title` | 12字以内 | — |
  | `question` | 24字以内 | — |
  | `claims[].text` | 20字以内 | 3件まで |
  | `claims[].source` | 10字以内 | — |
  | `facts` / `unknowns` | 1件18字以内 | 合わせて4件まで |
  | `options[].label` | 12字以内 | — |
  | `options[].note` | 20字以内 | — |

  資料の `title` と各論点の `title` は、改行したい位置に `\n` を入れられる（例 `"集客の打ち手、\nやる・やらない"`）。入れないと語の途中で折り返すことがある。

  例：✕「発表の準備が重いので、回数より1回の中身を厚くしたいという声が多かった」→ ○「回数より中身を厚く」。ビルドすると、目安を超えた項目が警告で出るので、直してからビルドし直す。
- 材料に機密そうな情報があっても、ページは外に出ないので入れてよい。ただし共有のしかたはユーザーに任せる。

## JSONの形

```json
{
  "title": "資料全体のタイトル",
  "subtitle": "任意：何のための確認か1文で",
  "date": "任意：2026-11-05",
  "lang": "ja",
  "items": [
    {
      "title": "論点の短い見出し（目次に出る）",
      "question": "〜にする？ の形の問い",
      "context": "任意：問いの背景を1〜2文",
      "claims": [{ "source": "資料名", "text": "その資料の言い分" }],
      "facts": ["わかっていること"],
      "unknowns": ["まだわからないこと"],
      "options": [
        { "key": "A", "label": "選択肢", "note": "選ぶと何が起きるか" },
        { "key": "B", "label": "選択肢", "note": "選ぶと何が起きるか" }
      ]
    }
  ]
}
```

任意の設定（トップレベル）：

| キー | 意味 |
|---|---|
| `lang` | `ja`（既定）か `en`。画面の文言とナレーションの言語が変わる |
| `narration` | `false` で最初からナレーションOFF |
| `sound` | `false` で最初から効果音OFF |
| `rate` | 読み上げの速さ（既定 1.05） |
| `voice` | 最初に使う声の名前の一部（例 `Nanami`、`Google`）。ページ下の声メニューで選び直すと、そちらを覚える |
| `footer` | 画面右下の小さな文字（「社外秘」など） |
| `id` | 回答の保存キー。同じタイトル・日付のページを別物として扱いたいときに使う |

`claims[].say` を入れると、その言い分だけ読み上げの文を変えられる（略語の読みを直したいときなど）。

完成例は `examples/sample.json`。

## ページの使い方（ユーザーに聞かれたら伝える）

- 「はじめる」で再生。論点ごとに 扉 → 決めること → 資料の言い分 → わかっていること → 選ぶ と進み、選ぶ画面で止まる。
- 選ぶ画面では、クリックするか数字キー（1〜3が選択肢、続く2つが「その他」「あとで決める」）で選ぶ。メモを書いて Enter か「次へ」で次の論点に進む。「その他」はメモが必須。
- キー操作：Space 再生/一時停止、→ 選ぶ画面へ（選ぶ画面では次の論点へ）、← 前の論点、M 目次、V ナレーション、S 効果音、F 全画面。
- 下の丸い番号で論点を行き来できる。色は 緑＝決定、紫＝その他、黄＝あとで。
- 回答はそのブラウザに保存されるので、再読み込みしても消えない。まとめ画面の「回答をコピー」で、Slackや議事録に貼れる文になる。
- 声は下のバーのメニューで選べ、選んだ声はブラウザに覚えられる。ブラウザの読み上げは音量を上げられないので、声が小さいときはPCの音量で上げる。
- ナレーションはブラウザの読み上げ機能を使い、端末内の声を優先する。端末内に声がなくオンラインの声しかないブラウザでは、読み上げる文がブラウザの提供元に送られることがある。気になる内容ならナレーションをOFFにする。
